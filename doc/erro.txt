# Mehfilista API - Error Codes & Messages

Complete reference of all possible error responses from the API for Flutter app implementation.

## Version

**v1.1.2** - Updated: February 8, 2026

## Production URL

```
http://20.83.180.133:9000
```

---

## Error Response Format

All errors follow this JSON structure:

```json
{
  "detail": "Human-readable error message"
}
```

OR with validation errors:

```json
{
  "detail": "Request validation failed",
  "errors": [
    {
      "type": "missing",
      "loc": ["body", "field_name"],
      "msg": "Field required",
      "input": {...}
    }
  ]
}
```

## HTTP Status Codes

| Code | Meaning | When to Show |
| --- | --- | --- |
| 200 | Success | Normal operation |
| 201 | Created | Resource created successfully |
| 400 | Bad Request | Show error message to user |
| 401 | Unauthorized | Redirect to login |
| 403 | Forbidden | Show "Access Denied" |
| 404 | Not Found | Show "Not Found" screen |
| 422 | Validation Error | Show validation messages |
| 500 | Server Error | Show "Something went wrong" |

## Common Error Patterns

### Invalid ObjectId Format

```json
{
  "detail": "Invalid ID format. Must be a valid ObjectId",
  "error": "'xyz' is not a valid ObjectId, it must be a 12-byte input or a 24-character hex string"
}
```

**Flutter Action:** Show: "Invalid ID format"

### Token Expired

```json
{
  "detail": "Token has expired"
}
```

**Flutter Action:** Logout user, clear token, redirect to login

### Network Errors (No Response)

**Flutter Action:** Show: "No internet connection. Please check your network"

### 500 Server Errors

```json
{
  "detail": "Internal server error"
}
```

**Flutter Action:** Show: "Something went wrong. Please try again later"

## Flutter Implementation Guide

### 1\. Create Error Handler Class

```dart
class ApiErrorHandler {
  static String getErrorMessage(Response response) {
    switch (response.statusCode) {
      case 400:
        return _handleBadRequest(response);
      case 401:
        return "Please login to continue";
      case 403:
        return "Access denied";
      case 404:
        return "Not found";
      case 422:
        return _handleValidationError(response);
      case 500:
        return "Something went wrong. Please try again";
      default:
        return "An unexpected error occurred";
    }
  }

  static String _handleBadRequest(Response response) {
    final data = jsonDecode(response.body);
    return data['detail'] ?? "Bad request";
  }

  static String _handleValidationError(Response response) {
    final data = jsonDecode(response.body);
    if (data['errors'] != null) {
      // Return first error message
      return data['errors'][0]['msg'];
    }
    return data['detail'] ?? "Validation error";
  }
}
```

### 2\. Show Appropriate UI

```dart
// For 404 - Show empty state
if (statusCode == 404) {
  return Center(
    child: Column(
      children: [
        Icon(Icons.search_off, size: 100, color: Colors.grey),
        Text("Not Found"),
        Text("The item you're looking for doesn't exist")
      ]
    )
  );
}

// For empty results - Show empty state
if (data.isEmpty) {
  return Center(
    child: Column(
      children: [
        Icon(Icons.inbox, size: 100, color: Colors.grey),
        Text("No Results"),
        Text("Try adjusting your filters")
      ]
    )
  );
}

// For errors - Show Snackbar
ScaffoldMessenger.of(context).showSnackBar(
  SnackBar(content: Text(errorMessage))
);
```

### 3\. Handle Token Expiry

```dart
if (response.statusCode == 401) {
  // Clear token
  await storage.delete(key: 'token');
  // Redirect to login
  Navigator.pushReplacementNamed(context, '/login');
}
```

## Best Practices for Flutter

1. **Always show user-friendly messages** - Don't show raw API errors
2. **Handle empty states** - Show helpful UI when lists are empty
3. **Cache data** - Reduce API calls and handle offline mode
4. **Retry logic** - Implement retry for network failures
5. **Loading states** - Show loaders during API calls
6. **Error logging** - Log errors for debugging (use Firebase Crashlytics)
7. **Token refresh** - Implement token refresh before expiry
